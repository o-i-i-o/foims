🔐 Certificate Management

Site Root CA

How to trust the site root CA

Windows: run "certutil -addstore -f Root foims-root-ca.crt" as administrator, or double-click the .cer file and import into Trusted Root Certification Authorities. Chrome/Edge/Firefox will all trust it after a browser restart.

Debian/Ubuntu: sudo cp foims-root-ca.crt /usr/local/share/ca-certificates/ && sudo update-ca-certificates; RHEL/Fedora: sudo cp foims-root-ca.crt /etc/pki/ca-trust/source/anchors/ && sudo update-ca-trust extract (the file must be PEM with .crt extension).

Linux Chrome/Chromium does not read the system trust store; additionally run: certutil -d sql:$HOME/.pki/nssdb -A -t "C,," -n "FOIMS-RootCA" -i foims-root-ca.crt (requires libnss3-tools/nss-tools).

Linux Firefox uses its own certificate store: import the CA manually under Settings > Privacy & Security > Certificates > View Certificates, or configure the p11-kit trust module via enterprise policy.

Import the root CA (not the site certificate); certificates must contain SAN entries. With a private CA, Chrome does not use local trust anchors for HTTP/3 (QUIC) and automatically falls back to TCP - this is expected behavior.

🗃️ Data Management

CSV Data Import

CSV Data Export

Instructions:

  • Import a ZIP of per-table CSV files (partial modules allowed) or a single CSV identified by its header row
  • Full import runs in order: Organization → Room → Network Region → Cabinet → Device → Cable Link → Visualization
  • References use business names (e.g. room/device); missing referenced resources abort and roll back
  • Rows are matched by business key: existing rows update, new rows insert with server-generated UUIDs; fields are trimmed automatically
