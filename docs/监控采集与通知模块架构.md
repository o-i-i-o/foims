## 0. 全局俯瞰：六个模块的相对位置

```
                        ┌────────────────── 被管对象 ──────────────────┐
                        │ Unix/Win 主机   网络设备   服务器 BMC        │
                        │  foims-agent    SNMP v1/2c/v3   IPMI RMCP+  │
                        │     │+Trap         │161/162          │623    │
                        └─────┼────────────────┼───────────────┼──────┘
       ①Agent采集(上报)       │                │ ②SNMP采集(直连)│③IPMI采集(直连)
                              ▼                ▼               ▼
              ╔══════════════ 各源汇聚：监控数据层 ═══════════════╗
              ║ monitored_hosts (source='agent'|'snmp'|'ipmi')   ║
              ║ host_metrics_history / host_alert_episodes       ║
              ║ devices/device_interfaces/snmp_arp_entries/...   ║
              ╚════════════════════╤═══════════════════════════╝
                                   ▼
              ④ 主机监控模块（聚合视图：/api/agents + SSE 实时）
                                   ▼
              ⑤ 告警判定 alert_episode（三源共用）
                                   ▼
              ⑥ 日志-通知模块（站内 notifications / 审计日志 / SSE）
                                   ▼
              ⑦ 通知推送模块（EMAIL / Webhook 通用·钉钉·企微 + syslog 外发）
```

三个最重要的结构性事实：

1. **三条采集管道互相独立，但汇入同一张 `monitored_hosts` 表**（`crates/foims-init/src/schema/tables/agents.rs:24` 的 CHECK `source IN ('agent','snmp','ipmi')`），由同一套告警引擎、同一个通知入口、同一组推送渠道收尾。
2. **`foims-agent-service` 名字有误导性**：它是主进程内的「agent 接入 + 采集服务」（服务端代码），由 `src/main.rs` 直接装配——QUIC 上报监听（main.rs:772）、Trap 接收（485）、SNMP/IPMI 实时 worker（530/543）、定时轮询任务注册（637-649）。它不是 agent 端模块。
3. agent 端工程在独立目录 `foims-agent/`（独立 workspace），与主仓通过受控共享协议类型对接（`foims-agent/crates/foims-protocol` 是 `foims-common/src/report.rs` 的人工同步副本）。

## 1. 主机监控模块

**定位**：agent 主机指标的采集聚合、存储、告警、实时可视化，并作为 SNMP/IPMI 两源数据的共用展示层。

### 1.1 数据流（agent 主路径，推模式）

```
foims-agent(每机)
  1s 采集(clamp 1..60) ──► 本地帧队列(120帧/8MiB,满弃最旧计dropped)
  10s 批量上报(±10%抖动) ──► POST /agent/v1/report   (QUIC HTTP3 + mTLS + Bearer令牌)
                              POST /agent/v1/realtime (秒级快照,只进内存)
      │ ingest.rs 鉴权→频控(upsert内联WHERE原子429)→逐帧校验→单事务upsert
      ├─► monitored_hosts 主行(首报自动注册,label保留用户改动)
      ├─► host_metrics_history 逐帧插入(UNIQUE(agent_id,collected_at)幂等)
      ├─► AgentLiveRegistry 内存注册表(collected_at单调合并)
      └─► alert_episode.evaluate_host 最后一帧4指标
                                   │ SSE 1s 节拍
                                   ▼
      GET /api/agents/live/stream (live_api.rs ──► 前端 AgentsPage.vue + useLiveAgents.ts)
```

其余两源为服务端轮询（拉模式）：`snmp_poll` 5 分钟全量（source='snmp'）、`ipmi_poll` 5 分钟（source='ipmi'），另有 SNMP/IPMI 秒级实时 worker（live_poll）。三源同表同告警，由 source 列区分。

### 1.2 关键文件

| 文件 | 职责 |
|---|---|
| `crates/foims-agent-service/src/ingest.rs` | 上报鉴权/校验/频控/入库（批量+实时双通道） |
| `crates/foims-agent-service/src/alerts.rs` | 告警阈值配置面（system_configs 读写校验+通知口径常量） |
| `crates/foims-agent-service/src/alert_episode.rs` | 告警 episode 状态机运行时（评估/落库/通知/兜底扫描） |
| `crates/foims-agent-service/src/live_poll.rs` | SNMP/IPMI 秒级实时 worker + Agent 实时注册表（内存） |
| `crates/foims-agent-service/src/live_api.rs` | `/api/agents/live` 全量快照 + `/live/stream` SSE |
| `crates/foims-agent-service/src/agents_api.rs` | 列表/Top榜/详情/历史曲线/label·status 维护/采集端口 |
| `crates/foims-agent-service/src/tasks.rs` | 调度执行器：agent_offline / 历史清理 / snmp poll / ipmi poll |
| `crates/foims-resource/src/device/host_monitor.rs` | 设备台账→SNMP 主机行管理地址联动 |
| `src/routes/mod.rs:904-961` | `/api/agents` nest 注册 + agent_admin_guard |
| `frontend/src/pages/AgentsPage.vue` | 主机监控页面 |
| `frontend/src/composables/useLiveAgents.ts` | 页面级共享单条 SSE（引用计数） |

### 1.3 告警状态机

- 阈值全局一套，存 `system_configs('agent','alert_thresholds')`：cpu/mem/disk/temp 阈值 + 持续 `for_secs`(15)、静默窗 `quiet_window_secs`(300)、冷却 `cooldown_secs`(600)、迟滞 `hysteresis_pct`(5)，默认禁用。
- Episode 纯函数状态机 `pending → active → resolved`（`Episode::step`, alert_episode.rs）：Over / Under / 迟滞带判定；Active 期间静默窗内**就地刷新**站内通知文案（60s 节流）而非新增行；跌破复位水位发恢复通知；Resolved 后再超标开新 episode 受冷却约束。
- **三条评估路径共用一个 AlertRuntime 单例**：① ingest 上报；② SNMP/IPMI 实时 worker；③ 每 300s 兜底扫描 `sweep_once`（负责停报复位，动态跳过已被实时覆盖的行）；重启后 `hydrate` 回灌历史 episode 不重复告警。
- 通知失败保持「未通知态」下轮重试——宁可重复不遗漏（仅站内通知有此语义）。

### 1.4 在线状态判定

| 来源 | 机制 |
|---|---|
| agent | 上报驱动 upsert 刷 last_seen；调度任务 `agent_offline` 每分钟：last_seen < 60s×offline_factor → offline（只对 agent 行生效） |
| snmp/ipmi | 各自轮询自翻转：连续失联 2 个轮询周期（间隔×2）→ offline |
| 前端实时态 | 以 SSE 快照 collected_at 新鲜度展示，在线状态仅兜底 |

### 1.5 数据表（见 agents.rs 建表）

| 表 | 说明 |
|---|---|
| `monitored_hosts` | 监控主行：machine_id 部分唯一、source CHECK、(device_id,source) 唯一、快照列 cpu/mem/disk/max_temp/uptime + raw_metrics JSONB |
| `host_metrics_history` | 时序：UNIQUE(agent_id, collected_at) 幂等，metrics 固定六键 {cpu,mem,disk,temp,rx_bps,tx_bps} |
| `host_alert_episodes` | PK(host_id, metric)，notify_ids 缓存站内通知行 ID |

告警配置非常规建表，存 `system_configs('agent','alert_thresholds')`。

## 2. SNMP 信息采集模块

**定位**：服务端主进程**直连**网络设备（async_snmp，UDP 161；Trap UDP 162），覆盖配置态 + 观测态 + 事件态。

### 2.1 三条路径

```
路径1 全量轮询(默认5min cron)          路径2 Trap被动接收          路径3 实时探针
snmp_poll.rs poll_all                 trap.rs start(UDP162)      live_poll.rs
  └ load_snmp_devices(snmp_enabled      └ community白名单(v1/v2c)   └ probe()在线探测
    AND status='online',凭据AES解密)    + 来源冷却限流(1024有界表)     → sample()秒级指标
  └ core按snmp_version建v1/v2c/v3      └ 解析PDU                  └ 写 monitored_hosts('snmp')
    会话(async_snmp, UDP161)           └【仅站内通知 snmp_trap,
  └ collect/mod.rs串十个子采集器:          不落snmp_events、不出站】
    sysinfo/ports/arp/vlan/lldp/cdp/
    entity/lag/poe/metrics
  └ 各子采集器直接upsert十张oid表
  └ 连续失败×2周期→offline自翻转
```

### 2.2 事件引擎与通知挂钩

`events/record_events`（events/mod.rs）在轮询后对比 ARP 表/接口状态/完整度，30 分钟抑制窗口内判定：

| 事件 | 持久化 | 站内 | EMAIL | WEBHOOK |
|---|---|---|---|---|
| link_flip（链路翻动）/ reboot | snmp_events | ✅ snmp_event | ❌ | ❌ |
| unknown_device（未知接入） | snmp_events | ✅ | ✅（mod.rs:296） | ✅（mod.rs:309） |
| arp_conflict | snmp_events（detail 存冲突 MAC） | ✅ | ❌ | ❌ |
| poe_off | snmp_events | ✅ | ❌ | ❌ |
| SNMP Trap/Inform | ❌ 仅瞬时 | ✅ snmp_trap | ❌ | ❌ |

### 2.3 下游联动

- `sync_switch_macs`（foims-resource/ip.rs）：接口 MAC 与 ARP 映射进 IP 资产绑定；`MacSyncTaskExecutor` 任务化。
- LLDP/CDP 邻居入 `device_lldps/device_cdps`（拓扑候选）。
- `debug/mib.rs`：任意 OID 即席查询（前端 SNMP 调试面板）。

### 2.4 关键落表

`devices`（snmp_* 凭据密文列）、`device_snmp`（poll_status/collect_flags）、`device_interfaces`、`snmp_arp_entries`、`device_lldps/cdps/vlans/entities/lags/poe_ports/sensors`、`device_inventory`、`snmp_events`（detail JSONB、severity CHECK）。

前端入口：设备弹窗 SnmpManage / SnmpDebug 组件、系统-SNMP 事件列表页。

## 3. Agent 信息采集模块

**定位**：agent 端二进制（独立 workspace）+ 服务端接入基建，即「被监控主机与 FOIMS 的全部信任与数据通道」。

### 3.1 agent 侧（foims-agent/，独立版本自管理）

| crate | 职责 |
|---|---|
| `foims-protocol` | 上报协议类型；与主仓 `foims-common/src/report.rs` 为人工同步受控副本 |
| `foims-agent-core` | metric 模型 / collector 编排（单采集 30s 超时 + 600s 卡死冷却）/ reporter：HTTP/3 mTLS 传输、帧队列、实时通道、证书续期 |
| `foims-agent`（Linux） | 40+ 只读 /proc//sys 采集器，逐字对照移植 node_exporter（meminfo/stat/diskstats/netdev/hwmon…） |
| `foims-agent-windows` | 对齐 windows_exporter 的 cpu/memory/disk/net/service 采集器 + SCM 服务态 |

`node_exporter/`、`windows_exporter/` 目录位于 foims-agent workspace 下，是上游 Go 参照源（fixture 对照用），不参与上报链路。

### 3.2 服务端侧

```
注册链:  Web生成注册令牌 ─► 下载配置包(zip/deb/rpm 现场组包, packaging.rs)
         ├ agent.toml(固定 collect=1s/report=10s) + ca.pem + client.pem/key
         ├ cert.rs rcgen 直签: server 证书 SAN=本机全部网卡IP; client 证书 clientAuth
         └ 复用判据: CA指纹一致 + SAN覆盖当前IP(agent_cert_sans 记录, 轮换/迁机自愈重签)
运时:    QUIC 监听 UDP:9100, WebPkiClientVerifier 仅锚站点 CA(report_server.rs)
         仅放行 POST /agent/v1/report|realtime|renew, 其余 404/405
信任:    站点 CA(证书管理页生成)双向锚 + Bearer 共享注册令牌二层
续期:    agent 剩余寿命<30天 → /agent/v1/renew; 服务端校验请求 DER ≡ mTLS 对端
         且 <90 天才重签 → 同步替换服务端磁盘物料 → agent 原子落盘换连
```

- **首报自动注册**：`machine_id` 不存在即建行（status=active、label=hostname），无激活流程；禁用行整批 403；删除后同机可重注册且 live 注册表按 machine_id 自愈。
- **批量帧约束**：帧值域校验（CPU/磁盘 [0,100]、温度 [-100,250] 防溢出、collected_at 时钟漂移 [过去≤24h, 未来≤300s]），帧间 machine_id 一致性整批校验。
- **版本分发**：agent 二进制包由 CI 直发 Release 页，自动升级未实现（`latest_version` 仅展示）；服务端只管配置包（含敏感令牌，admin/secadmin 专属）。deb `Depends: foims-agent`、rpm `Requires: foims-agent`，postinst/%post 统一 enable+restart。

## 4. IPMI 信息采集模块

**定位**：服务器 BMC 带外指标，纯 Rust 实现（`ruipmi::IpmiClient` RMCP+，UDP 623），不调 ipmitool、无子进程。

- **与 SNMP 同构的采集节奏**：5 分钟全量轮询（ipmi_poll `poll_all` → foims-ipmi `collect` → `read_sensors` 遍历 SDR 逐个 Get Sensor Reading）+ live_poll 的 IPMI 秒级槽位（温度/风扇/电压/电源）。
- 鉴权：RAKP（cipher suite sha256/sha1 可配），密码 AES-256-GCM 密文落库，续写「留空=保留」防回显泄露。
- 落表形态较轻：`devices` 的 ipmi_* 列 + `device_inventory`（BMC 资产）+ `monitored_hosts(source='ipmi')`；历史仅写 `temp` 一个键（有意取舍，注明于 ipmi_poll.rs）。
- 告警：与 SNMP/agent 三源共用同一 episode 管线与阈值集。
- API：`devices` 侧配置 CRUD + `test-ipmi` 即席连测（复用 SNMP 同款 SSRF IP 校验）。

## 5. 日志-通知模块

**定位**：站内通知的查询/已读 + 审计日志（操作/登录）+ 运行日志 SSE + syslog 外发。

```
通知产生源(5类写 notifications 表)          统一入口
ip_change(含设备更换)  ip.rs mac_sync轮询 ─► create_notification
agent_alert            alert_episode        (foims-snmp/src/events/notify.rs:22)
snmp_event             snmp events(仅5类)      逐管理员 user_id 各写一行
snmp_trap              trap.rs UDP接收         content 存 {"key":i18n,"params":{}}
[历史遗留 mac_change 存量孤儿行]
                     ▼
查询/已读: GET /api/notifications、PUT /{id}/read、PUT /mark-all-read
           (src/log/notification.rs, 归属校验 + ORDER 白名单)
                     ▼
审计链: log_op_best_effort(foims-auth/meta.rs, 全仓 84 处调用)→operation_logs+syslog 钩子
        log_login(login/mod.rs)→login_logs+syslog
        站内通知写库失败「下一轮观测重试」仅 agent_alert 有效, 其余直接丢
运行日志: tracing→LiveLogLayer→broadcast(512)→SSE /api/logs/live
             (i18n 语言过滤, 慢消费者 Lagged 转「跳过 N 条」占位, 15s keepalive)
外发: forwarding.rs RFC3164 syslog(UDP/TCP, local0, 3s 预算, 30s 配置缓存,
      信号量 16 并发饱和即丢) —— 仅操作/登录日志, 不含通知与事件
清理: log_cleanup 定时任务(op/login/notifications) + 手动 /api/system/logs/clear
      agent_history_cleanup 兼管 host_metrics_history + snmp_events
```

权限矩阵：`/api/logs/**` 仅 admin/auditor（routes/mod.rs:139-143）；站内通知按登录用户隔离。

关键表：`notifications`（user_id FK、notification_type VARCHAR(20)、content i18n JSON）、`operation_logs`（action/resource_type/details JSONB/success/ip）、`login_logs`、`snmp_events`、`task_logs`。

## 6. 通知推送模块

**定位**：站内通知之外的出站渠道（EMAIL/Webhook）：配置、过滤、加密、发送、测试。

### 6.1 配置存储（全部走 `system_configs` KV 表）

| config_type/key | 内容 |
|---|---|
| `notification/email_recipients` | `[{user_id, ip_change, agent_alert, snmp_event}]` 三订阅 bool |
| `smtp/*` | host/port/username/密码(AES密文)/from/secure |
| `webhook/targets` | `[{id,name,channel(generic/dingtalk/wecom),url,secret(密文),ip_change,agent_alert,snmp_event}]` |
| `log_forwarding/*` | syslog 外发（属日志模块域） |

`NotifyKind` 三值（smtp.rs）：`ip_change` / `agent_alert` / `snmp_event`（IP 变更与工位设备更换语义归并共用 ip_change）；`NotifyScope` 三 bool 与之对应，serde 缺省**按启用**（「多发代价远小于静默漏报」）。密钥类（SMTP 密码、钉钉加签 secret）AES-256-GCM 密文落库，回显只给 `has_password`/`has_secret`。

### 6.2 业务事件 → 出口矩阵

| 业务源 | 站内 | EMAIL | Webhook |
|---|---|---|---|
| IP 变更 / 工位设备更换 | ✅ notify.rs:98/171 | ✅ notify.rs:115/188 | ✅ notify.rs:133/209 |
| 主机告警 agent_alert | ✅+静默窗就地刷新 | ✅ alert_episode.rs:784 | ✅ alert_episode.rs:803 |
| SNMP unknown_device | ✅ | ✅ events/mod.rs:296 | ✅ events/mod.rs:309 |
| link_flip/reboot/arp_conflict/poe_off | ✅ | ❌ | ❌ |
| SNMP Trap | ✅ | ❌ | ❌ |
| agent 掉线 / 设备离线翻转 | ❌ | ❌ | ❌ |

### 6.3 发送实现要点

- 钉钉：markdown 消息 + HMAC-SHA256 加签（`timestamp\n{secret}` → Base64 → URL 转义），有官方口径回归测试。
- 企业微信：text 消息；generic：`{title,message}` JSON。
- 业务级失败判定：2xx 但 `errcode≠0` 仍判失败（post_json）。
- 可靠性取舍：全部渠道**无重试、无投递账本**，失败仅记日志；单渠道/单目标失败互不影响；站内通知是唯一可靠性锚点。
- 测试端点（webhook test、smtp test、syslog 试发）错误直接向上传播，与业务静默降级相反；webhook test 只能测试**已保存**目标（复用已存加密密钥）。

## 7. 三条采集管道的结构同构性

| 维度 | agent | SNMP | IPMI |
|---|---|---|---|
| 采集方向 | agent 上报（推） | 服务端直连（拉）+ Trap | 服务端直连（拉） |
| 5min 全量落库 | ingest 批量 | 十张 OID 表 | devices ipmi 列 |
| 秒级实时 | realtime 通道 | live probe+sample | live IPMI 槽位 |
| 离线判定 | offline 任务 60s×factor | 轮询自翻转 ×2 | 轮询自翻转 ×2 |

## 8. 值得留意的设计问题

按「先一致性、后可靠性、再扩展性」排序，作为后续演进的备忘输入（详细方案另行讨论）：

1. **收件人角色口径漂移**：站内通知收件人三种口径并存——`admin+secadmin`（ip_change、snmp_event）vs `admin+sysadmin+secadmin`（agent_alert、snmp_trap），同一「全体管理员」语义无统一策略源。
2. **通知入口跨 crate 越界**：`create_notification` 是全系统唯一通知入口，却放在 `foims-snmp` crate，宜下沉。
3. **`get_device_ip_address` 三份同构 SQL**（snmp-core / ipmi-core / resource-lldp）。
4. **SNMP Trap 无持久化、无外发**：不落 snmp_events 也无邮件/Webhook，清理后无审计痕迹。
5. **推送覆盖缝隙**：link_flip/reboot/arp_conflict/poe_off、agent 掉线均无外部推送。
6. **IP 变更去重脆弱**：`content LIKE '%"mac":"..."%'` 全表扫描 + `unwrap_or(false)` 吞查询错误（DB 故障时全量重发）。
7. **存储治理缺失**：`host_metrics_history` 高频增长无分区/BRIN，仅 DELETE 滚动清理；`task_logs` 无任何清理通道。
8. **协议卫生**：`source` CHECK 焊死三值（扩 Redfish 需迁移）；`collectors` 控制面协议预留未实装；`latest_version` 回传服务端版本号语义错位。
9. **连接面风险**：每机常驻两条 QUIC 连接，h3 accept 无背压/连接数配额（realtime 仅读内存是好的一面）。
10. **IPMI 采集面空白**：`ipmi_port` 列仅展示语义（硬编码 623）、Compact SDR 被跳过会折损部分 BMC 读数、SEL/FRU 未接入使 BMC 本地告警面为空。
11. **存量孤儿**：`notification_type='mac_change'` 存量行无迁移归属；LLDP/CDP 邻居已采集但拓扑自动连线未消费。
