# 重构方案：信息点移入房间 + 新"线路"模块（整合 cable_links）

## 架构决策（已与你确认）

1. **`net_outlets` 表名/标识符保留不变** — 它成为"信息点"（物理点位），创建/管理移入房间模块（内联编辑 + 列表弹窗，参照工位/机柜，所有房型）。
2. **资源管理的"线缆"tab 改名为"线路"** — 基于现有 `cable_links` 表（已有后端 CRUD + path 查询），通过改造原 net_outlet 前端为其建立 UI。
3. **本次删除 `net_outlets` 的 peer_* 四字段及 `device_interfaces.net_outlet_ids` 链验证逻辑** — 连接统一由"线路"(cable_links) 表达，消除重复逻辑。
4. **DB 修改**：手动 SQL 迁移现有部署 + 同步更新 `ipma-init` 的 `CREATE TABLE` 初始化代码。无启动时自动迁移框架。

## 风险与缓解
- **net_outlets 表名不变** → 现有 cable_links 的 `'net_outlet'` 枚举字面量、device_interfaces 清理、索引全部兼容，迁移风险最低。
- **peer_* 删除** → 彻底去除重复逻辑，但需确保 cable_links UI 完全覆盖原 peer 场景（信息点↔信息点、信息点↔交换机口）。路径查询 `find_cable_path` 已支持。
- **无启动迁移** → 提供 `migrations/rename_peer_removal.sql` 手动脚本 + README 说明；新环境由 ipma-init CREATE 直接建干净结构。
