# 信息点/配线架概念分离重构方案

## 目标
1. **信息点 = 网络插座**：`net_outlets` 表去掉 `outlet_type`、`cabinet_id` 分类字段，信息点仅隶属房间
2. **配线架独立表**：新建 `patch_panels` 表，隶属机柜（`cabinet_id NOT NULL`）
3. **线路端点类型保持三类**（UI）：信息点 / 设备接口（含设备端口，前缀编码合并）/ 配线架（改指新表）；DB 四类 CHECK 不变
4. **设备接口端点新级联**：房间 → 机柜（可选"不限"）→ 设备 → 端点

---

## 一、数据库迁移（按 AGENTS.md 直接 psql 修改，不写迁移代码）

新建 `scripts/patch-panel-split.sql` 并执行（先 `pg_dump` 备份 ipma 库）：

1. **数据修正**：`cable_links` 中 endpoint_type='net_outlet' 但实际指向 patch_panel 行的端点改为 'patch_panel'，并按 `chk_endpoint_order` 规则重排 A/B 端
2. **建表**：
   ```sql
   CREATE TABLE patch_panels (
       id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
       name VARCHAR(100) NOT NULL,
       cabinet_id UUID NOT NULL REFERENCES cabinets(id) ON DELETE CASCADE,
       created_at/updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
       CONSTRAINT uq_patch_panels_name UNIQUE (cabinet_id, name)
   );  -- + idx_patch_panels_cabinet_id + updated_at 触发器
   ```
3. **迁移数据**：`INSERT INTO patch_panels SELECT id,name,cabinet_id,created_at,updated_at FROM net_outlets WHERE outlet_type='patch_panel' AND cabinet_id IS NOT NULL`（保留原 id，线路引用不断链）；被线路引用但 cabinet_id 为空的孤儿行→脚本报错中止人工处理；未引用孤儿→删除
4. **net_outlets 精简**：删除已迁移行；`DROP COLUMN outlet_type, DROP COLUMN cabinet_id`；删 `idx_net_outlets_cabinet_id`
5. **重建触发器/函数**（均 `CREATE OR REPLACE`/先 DROP）：
   - `validate_cable_link_endpoints()`：patch_panel 分支改查 `patch_panels`
   - `prevent_net_outlet_deletion_if_linked()`：仅匹配 'net_outlet' 类型
   - 新增 `prevent_patch_panel_deletion_if_linked()` + 触发器（级联删除时同样生效，机柜删除受保护）
   - `find_cable_path()`：patch_panel label 分支改查 `patch_panels`
6. **重建视图**：`net_outlets_with_details`（去 outlet_type/cabinet 列）、`cable_links_with_details`（patch_panel label 来自新表）、新增 `patch_panels_with_details`（join cabinets+rooms）
7. OWNER/GRANT 归 `ipma` 用户；`sudo -u postgres psql -d ipma -f scripts/patch-panel-split.sql` 执行
